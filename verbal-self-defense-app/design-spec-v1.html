Verbal Self-Defense App
Design Specification v1.0

Android Kotlin + Jetpack Compose On-Device ML Privacy First

1. Product Overview

An Android app that runs as a foreground service, continuously monitoring ambient conversation through the device microphone. When it detects language patterns indicative of PUA tactics, gaslighting, verbal escalation, or insults, it alerts the user through escalating haptic and visual signals (vibration + edge lighting, orange → red). The user triggers a retort via double-tap or triple-knock gesture, and the app speaks the response through the device speaker.

Core Problem
People freeze in verbal conflict situations. This app gives them a prepared, calm response.
Target User
Individuals who face frequent verbal pressure and want real-time social defense.

2. Usage Scenarios

Decision: All three, switchable by user mode.

👔 Workplace
Colleague/manager PUA, blame-shifting, passive aggression. Retorts should be rational, professional, firm.
🍻 Social
Dinner parties, drinking culture, unsolicited comments. Retorts should be witty, sharp, humorous.
❤️ Relationship
Gaslighting, emotional blackmail, boundary violations. Retorts should be gentle → firm → assertive.

3. Retort Speed Architecture (3-Layer)

Key insight: AI is too slow for the first retort (on-device 0.5-2s, cloud 3s+). The first response must use preset library for <200ms delivery.

Layer 1 — First Strike (<200ms)
Detection → context match → TTS playback. Double-tap to deploy. Zero AI latency. Uses pre-written retort library.
Layer 2 — Stalling (Backup)
Universal phrases: "Say that again?", a laugh, "Interesting." — buys 2-5 seconds for AI to generate a proper follow-up.
Layer 3 — AI Follow-Up (5-15s window)
On-device LLM generates context-aware retort considering the full conversation context, threat level, and user tone preference. User previews on screen, confirms with double-tap.

4. Retort Library Structure

Three-dimensional organization: Scenario (3) × Tone (5) × Threat Level (3). Each cell contains 2-4 preset phrases. Total: ~180-360 initial phrases.

Scenario
Workplace / Social / Relationship
Tone
Gentle / Rational / Sharp / Blunt / Humorous
Threat Level
L1 Passive / L2 Escalation / L3 Attack

Classification Rules

  1. Match Scenario First — Current app mode acts as primary filter.
  2. Escalate Tone with Threat Level — L1→Gentle/Rational, L2→Sharp/Rational, L3→Blunt/Sharp or user's combat mode.
  3. User Tone Preference as Weight — +30% selection weight to user's preferred tone per scenario.
  4. Diversity within Session — Recency penalty prevents repeating the same retort.

5. User Interaction Flow

1
Monitor — Foreground service with persistent notification. On-device VAD + STT.
2
Alert — Threat detected. Screen edge glow (orange/red) + haptic feedback.
3
First Strike — Double-tap → preset retort TTS playback (<200ms). No waiting.
4
AI Generates Follow-Up — Background LLM inference. Shows suggestion on screen within 10s.
5
Confirm & Speak — Quick glance → double-tap to deploy, or swipe to see alternatives.

6. AI Generation Strategy

Trigger
Activated after first retort finishes + at least 2 more speech exchanges detected.
Context Window
Last 30s of transcript + speaker IDs + threat level + tone preference.
Dual-Track Generation
Quick (0.5-2s): Template slot-filling (insert detected name/org). Full (3-8s): On-device 1-3B quantized LLM.
Quality Guardrails
Max 2 sentences. No swearing by default (configurable). De-escalation bias unless combat mode is on.
Fallback
LLM timeout or low quality → fallback to second-best preset retort.

9. Risk Mitigation

🔴 Privacy
All processing on-device. Transparent data policy. Visual recording indicator.
🔴 Legal
No permanent audio storage. Acts as "hearing aid." Consult local wiretapping laws.
🟡 Battery
Adaptive sampling. Efficient quantized models. Wake-lock with debounce.
🟡 False Positives
Tunable sensitivity. Learning mode. User-calibrated thresholds.
🟢 Play Store
Target sideload. If Play Store needed, foreground service + RECORD_AUDIO justification.
