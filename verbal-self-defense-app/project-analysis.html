Project Overview

An Android app that runs in the background, continuously monitoring ambient conversation. When it detects language patterns that are PUA (pick-up artist) tactics, gaslighting, verbal escalation, or outright insults — it alerts the user through escalating haptic and visual signals. The user can then trigger a pre-generated retort through the speaker with a simple double-tap or triple-knock gesture.

Core Need

People in verbally disadvantaged situations often freeze, regret not speaking up, or escalate emotionally. This app gives them a calm, prepared response — in their own voice or chosen tone.

Target User

Individuals who find themselves in frequent verbal conflicts, social pressure situations, or want a "second brain" for real-time social defense. Self-defense isn't just physical.

Core Features

1. Ambient Audio Monitoring

Always-on

Runs as a foreground service with persistent notification. Uses the device microphone to capture ambient audio. Privacy note: all audio processing happens on-device. No data leaves the phone.

2. Voice Identification

Speaker Diarization

Identifies different speakers by voice characteristics. Maps phrases to individuals so you know exactly who said what. Builds a temporary session profile of each speaker's tone and aggression level.

3. Threat Level Detection

Multi-Layer

Three-tier alert system:

Level 1 - Awareness Orange running light, subtle vibration
Level 2 - Warning Fast orange-red pulse, medium vibration
Level 3 - Defend Red strobing light, strong vibration pattern

4. Smart Retort Engine

Multi-Tone

Pre-written or AI-generated retorts organized by tone and intensity:

Gentle / Soft Rational / Factual Firm / Assertive Sarcastic / Witty Aggressive / Blunt

5. Gesture Trigger

Quick Access

Activation: Double-tap or triple-knock on the screen. The app then speaks the selected retort through the device speaker (or connected audio output). The response can be context-aware — the app picks the most appropriate retort based on what was just said.

6. Session Review & Learn

Post-Event

After a verbal encounter, review what happened, what was said, and how you responded. The app helps you reflect: "Next time, I could have said..." — turning every difficult conversation into a learning opportunity.

Technical Architecture

High-level component breakdown for the Android application:

Audio Pipeline

Microphone → AudioRecord Buffer → VAD (Voice Activity Detection)
    → Speaker Diarization → ASR (Speech-to-Text) → Text Analysis

Key choices: on-device ML models for privacy. VAD using WebRTC VAD, speaker diarization via on-device embeddings, STT using on-device models (e.g., whisper.cpp or ML Kit). Text analysis with lightweight on-device NLP for threat classification.

Threat Classification

Text → Keyword Detection (fast path) → Pattern Analysis → LLM/NLP Classification
    → Sentiment Scoring → Escalation Detection → Level Output (1-3)

Two-pass system: a fast keyword/pattern pass for immediate detection, followed by a deeper semantic analysis for context understanding.

Retort Engine

Detection Result → Context Builder → Retort Selector (Rule/LLM)
    → TTS Engine → Speaker Output

Retorts can come from a curated local database (editable by the user) or generated on-the-fly by an on-device LLM based on context.

App State Machine

IDLE → LISTENING → ANALYZING → ALERTING → RETORT_READY → SPEAKING → IDLE

Clean state transitions with proper lifecycle management for the foreground service. Battery optimization: audio processing is batched and throttled during quiet periods.

Risk Assessment & Compliance

Building a real-time audio monitoring app comes with significant responsibilities. Here is the risk matrix and mitigation strategy for each category.

Risk Category Level Description Mitigation
Privacy & Audio Data High Always-on microphone is a privacy minefield. Users near the app user may not consent to recording. All processing on-device. No network audio stream. Clear visual indicator when recording. User consent screen on first launch. Transparent data policy.
Legal (Recording Consent) High Recording conversations without consent may violate wiretapping laws in some jurisdictions (varies by country/state). Localized legal warnings. The app acts as a "hearing aid" for the user (not recording storage). Consult legal advice per target market.
Battery Drain Medium Continuous audio processing + on-device ML = significant battery impact. Adaptive sampling: lower frequency during quiet periods. Wake-lock with debounce. Efficient ML models (quantized, small).
False Positives Medium App triggering alert for normal conversation could cause embarrassment or unnecessary conflict. Tunable sensitivity. Learning mode: app starts in passive mode, only alerts after user calibrates. User sets their own thresholds.
Retort Misuse Medium User could use the app to escalate conflicts or be aggressive when it is not warranted. Default to de-escalation tones. "Cool-down" period before retort trigger. User must actively choose to retort (not automatic).
Play Store Compliance Medium Google Play restricts apps that record audio in the background. Accessibility API restrictions also apply. Use foreground service with persistent notification. Declare RECORD_AUDIO with justification. Consider sideload/distribution outside Play Store.
Model Accuracy Low Chinese-language NLP for detecting PUA/gaslighting patterns is not a well-studied domain. Build a curated phrase library first. Use rule-based detection for known patterns. Add ML classification as a later enhancement.

Brainstorming Design Decisions

Decisions made during WorkBuddy brainstorming session, June 4, 2026.

1. Usage Scenarios

Decision: All three scenarios covered, switchable by mode.

👔 Workplace / Office 🍻 Social Gatherings ❤️ Relationships / Family

2. Retort Speed Architecture

Decision: Three-layer speed system. AI is too slow for the first retort (on-device: 0.5-2s, cloud: 3s+), so the first response must use preset library for <200ms delivery.

Layer 1 — First Strike (Preset, <200ms)
Detection → context match → TTS playback. Double-tap to deploy. ZERO latency.
Layer 2 — Stalling (Backup)
Universal phrases: "Say that again?", a laugh, "Interesting." — buys 2-5 seconds for AI to generate.
Layer 3 — AI Follow-Up (5-15s window)
On-device LLM generates context-aware retort. User previews on screen, double-taps to deploy.

6. Retort Classification Rules

The auto-matching engine selects the best retort based on this ruleset:

Rule 1: Match Scenario First
The current app mode (Workplace/Social/Relationship) acts as the primary filter. Only retorts tagged for that scenario are considered.
Rule 2: Escalate Tone with Threat Level
L1 (passive aggression) → Gentle or Rational tone default.
L2 (escalation) → Sharp or Rational tone, user's last-used preference.
L3 (attack) → Blunt or Sharp tone, or user's pre-configured "combat mode" tone.
Rule 3: User Tone Preference as Weight
Each user can assign a "default tone" per scenario. This adds a +30% selection weight to that tone, but the engine can override if the threat level demands escalation.
Rule 4: Diversity within Session
Avoid repeating the same retort within the same conversation session. Track recently used phrases per scenario and deprioritize them (recency penalty).

7. AI Generation Strategy

For follow-up retorts (Layer 3), the on-device LLM uses this strategy:

Trigger
Activated when first retort finishes playing AND at least 2 more exchanges are detected.
Context Window
Last 30 seconds of transcribed conversation + detected speakers + current threat level + user's tone preference.
Generation Type
Quick (0.5-2s): Template-based slot filling. Fill detected name/organization into sentence templates.
Full (3-8s): On-device LLM (1-3B param, quantized). Generates from scratch with tone instruction.
Quality Guardrails
Max 2 sentences (keep it punchy). No swearing by default (configurable). No escalation escalation — AI tends to de-escalate unless user's combat mode is on.
Fallback
If LLM times out or produces low-quality output, fall back to second-best preset retort from the library.
